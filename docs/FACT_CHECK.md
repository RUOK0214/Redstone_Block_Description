# 정보 확인 기록

대상은 Minecraft Java 26.2, 기본 게임 틱 속도입니다. 2026-10-31에 한국어·영어 설명과 새 수량표·보충 정보를 검토했습니다.

## 근거

- 공식 Minecraft 26.2 클라이언트의 블록 상태·레지스트리와 동작 코드를 기준으로 수치를 확인했습니다.
- `src/gametest/java/io/github/ruok0214/redstonehelp/MechanicsChecks.java`는 별도 게임 월드에서 새 설명의 주요 수치를 검사합니다.
- `ExpandedMechanicsChecks.java`는 수량표와 추가 블록의 출력을 게임의 실제 계산과 비교합니다. `CatalogAudit.java`는 비교기 출력 블록과 발사기 동작 레지스트리를 조사합니다.
- 구리 블록의 산화 단계에 따른 트럼펫 음색은 [공식 Java 26.1 변경 기록](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-1)에서 추가된 기능이며, 26.2 게임의 악기 레지스트리와 직접 대조했습니다.
- 선반의 교환 동작은 [공식 Copper Age 변경 기록](https://feedback.minecraft.net/hc/en-us/articles/39966147272589-Minecraft-Java-Edition-1-21-9-The-Copper-Age), 돌풍구의 블록 조작은 [공식 1.21 변경 기록](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-21), 크리킹 심장의 거리 출력은 [공식 1.21.2 변경 기록](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-21-2)과 해당 26.2 클래스의 동작을 대조했습니다.

## 보관함 자체의 기능과 가마솥 날씨 정보

0.6.0에서는 보관함의 공통 비교기 설명 앞에 각 블록의 기본 기능을 추가했습니다.
공식 26.2 클라이언트의 다음 구현과 기본 조리법을 직접 확인했습니다.

- `ChestBlock`, `BarrelBlock`: 상자 위 전도성 블록·앉은 고양이의 열림 방해와 통의 열림 동작.
- `ShulkerBoxBlock`, `ShulkerBoxBlockEntity`: 27칸, 뚜껑 공간, 내용물 보존과 셜커 상자 중첩 금지.
- `AbstractFurnaceBlockEntity`, `SmeltingRecipe`, `BlastingRecipe`, `SmokingRecipe`: 호퍼 삽입·추출 방향과 기본 처리 시간 200·100·100게임 틱.
- `BrewingStandBlockEntity`: 5칸, 양조 400게임 틱, 블레이즈 가루당 연료 20회.
- 구리 상자의 분류 역할은 [공식 구리 골렘 소개](https://www.minecraft.net/en-us/article/copper-golem)와 게임의 상자 등록 정보를 대조했습니다.
- [공식 Java 1.17 변경 기록](https://feedback.minecraft.net/hc/en-us/articles/4402626897165-Minecraft-Caves-Cliffs-Part-1-1-17-Java)은 강설 중 가마솥에 가루눈이 모이는 기능을 설명합니다. `ServerLevel.tickPrecipitation`, `CauldronBlock`, `LayeredCauldronBlock`에서 실제 강수·생물 군계 조건, 지붕에 가리는 조건, 내용물 종류별 증가를 확인했습니다.
- `CauldronInteractions`와 `cauldron_can_remove_dye` 아이템 태그에서 양동이·물병 사용, 장비·셜커 상자 염색 및 깃발 마지막 무늬 제거, 물 한 단계 소모를 확인했습니다. [공식 가마솥 소개](https://www.minecraft.net/en-us/article/cauldron)에 나오는 Bedrock 전용 물약·염색한 물 기능은 Java 설명과 구분했습니다.

강설 장면은 별도 게임 월드에서 빈 가마솥에 실제 강수 처리 함수를 적용해 가루눈 3단계가 되는 것을 검사하고 촬영했습니다.
비·지붕·점적석·세척의 모든 조합을 인게임 자동 검사한 것은 아니며, 해당 조건은 게임 동작 코드로 확인했습니다.

## 0.7.0 수량표·음반·진동 정보

- 수량표 제목은 문법 차이보다 인과관계가 모호한 표현을 바로잡기 위해 변경했습니다. 최대 겹침 개수와 전체 낱개 수를 구분하고, 아이템 수 → 비교기 출력 순서로 표를 읽게 했습니다. 계산값은 기존 검증값을 유지합니다.
- 공식 26.2 클라이언트의 `data/minecraft/jukebox_song/*.json` 22개와 실제 음반 아이템을 모두 대조했습니다. `GuideTables.TRACKS`에 곡 제목과 기본 비교기 출력을 기록하며 `ReferenceChecks`에서 누락과 출력값을 검사합니다. 최신 곡 Bounce의 출력 8은 [공식 26.2 변경 기록](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-2)에서도 확인할 수 있습니다.
- `JukeboxBlockEntity.getComparatorOutput`은 들어 있는 음반을 읽으며 재생 상태를 조건으로 삼지 않습니다. 실제 월드에서 재생 중 일반 출력 15, 정지 후 일반 출력 0, 유지되는 비교기 출력, 제거 후 비교기 출력 0을 22종 모두 확인했습니다. 바로 아래 위치에 전원이 전달되는 것도 검사했습니다.
- `VibrationSystem`의 주파수 대응에서 표의 대표 이벤트 15개를 직접 대조합니다. 표는 각 주파수의 대표 예이며 모든 이벤트를 열거하지는 않습니다. 같은 주파수의 공명은 [공식 Java 1.20 변경 기록](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-20)과 `SculkSensorBlock.tryResonateVibration`의 여섯 면 검사에 근거합니다.
- `vibration_resonators` 태그에는 일반 자수정 블록만 포함됩니다. `occludes_vibration_signals`에는 양털 블록, `dampens_vibrations`에는 양털과 양탄자가 포함됩니다. 32개 색상 변형의 태그와 실제 수신기의 양털·양탄자 차단 차이, 설치 이벤트 억제를 검사했습니다.
- 자수정 장면에서는 첫 감지체의 입력 주파수 1이 다른 감지체에서도 1로 수신되는지와 조명 점등을 검사했습니다. 물에 잠긴 감지체의 소리와 출력 조건은 `SculkSensorBlock.activate` 및 비교기 출력 코드를 확인했습니다.

발사기의 등록 동작뿐 아니라 장착 가능 아이템·생성 알·유황 큐브 먹이 태그에 대한 기본 분기까지 확인했습니다.
표는 최대 묶음 크기가 같은 아이템으로 채운 경우입니다. 서로 다른 묶음 크기의 아이템이 섞이면 칸별 채움 비율이 필요하며, 수량표 하나로 합산하지 않습니다.
일반 보관함 계산과 달리 선반·조각된 책장·벌집·케이크 등의 고유 출력에는 이 수량표를 붙이지 않습니다.
모든 회로·리소스 팩·다른 모드와의 조합을 검증한 것은 아닙니다. 사진은 고정된 상태 예시이며 1.8초 전환 주기가 실제 회로 지연 시간을 뜻하지 않습니다.

## 표현 검토

- 0.7.1 전체 점검에서는 71개 주제의 기본·상세 문장, 한국어·영어의 표와 사진 설명을 대조했습니다. 양탄자의 잘못된 조사를 수정하고, 비교기가 읽는 수치를 블록이 직접 내는 전원처럼 보이지 않도록 구분했습니다.
- 소제목과 내용의 대응도 검토해 벌집의 수확·정박기의 충전 설명을 비교기 항목에서 분리했습니다. 선반의 뒤쪽 읽기는 비교기 항목으로 옮기고, 독서대의 두 종류 출력을 나눴습니다.
- `LecternBlockEntity.getRedstoneSignal`의 한쪽짜리 책 예외를 확인했습니다. 실제 월드에 1·2·5쪽의 쓰인 책을 넣어 첫 페이지와 마지막 페이지의 값을 대조했습니다.
- `SculkSensorBlock.activate`는 물에 잠겨도 활성화·전원·공명 처리를 유지하고 자체 활성화 소리만 생략합니다. 일반·조율된 감지체의 물에 잠긴 상태에서 직접 진동을 받아 신호와 주파수 10을 출력하는지 검사했습니다.
- 중계기 잠금은 다른 중계기·비교기의 **출력 방향이 옆면을 향한다**는 의미가 드러나게 수정했습니다.
- 호퍼의 출구를 항상 아래로 해석할 수 있는 표현을 수정했습니다.
- 구리 전구는 전원을 끊어도 현재 켜짐·꺼짐 상태를 유지한다는 점을 분명히 했습니다.
- 소리 블록의 위 공간과 머리 블록의 소리 조건을 구체화했습니다.
- 게임 내 한국어 이름에 맞춰 동력 레일이라는 표현을 사용했습니다.
- 상자·통 등의 기존 공통 비교기 문장은 한국어·영어 모두 유지하고 ‘비교기 출력’으로 옮겼습니다. 각 블록의 요약과 기본 작동은 자체 기능으로 보충했습니다.
- 덫 상자·독서대·퇴비통·주크박스의 기존 정보를 유지했습니다. 독서대·퇴비통은 기본 용도를 보충했으며, 덫 상자에는 보관·열림 조건을 추가하고 자체 신호와 비교기 출력을 구분했습니다.
